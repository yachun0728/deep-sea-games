# 按核准設計稿實作

使用者確認設計稿，就是要求正式畫面照該稿實作。設計稿是視覺驗收基準，不只是配色或氣氛參考。

## 實作約束

- 開始前查看核准原圖，確認採用的版本與範圍；保存原檔，保留後續版本，不覆寫核准紀錄。已確認的設計不用再次詢問畫風。
- 忠實保留角色身份、輪廓、頭身比、體型、五官、表情、服裝與道具，並保留場景視角、構圖、光線、材質、線條、細節密度及整體畫風。介面的形狀、層級、位置與角色在手機畫面中的相對大小也須對照。
- 正式素材應從核准圖提取或以核准圖作為參考製作。生成角色、動作或場景素材時，必須把核准圖傳給可用的工具作為參考，不能只用文字重新猜畫。拆層、裁切及動畫須維持角色與場景一致性。
- 不得自行把手繪、卡通 3D 或其他核准畫風改成簡單幾何形狀、通用圖示、Emoji、粗略 SVG／Canvas 人物或佔位素材；換成相同配色也不算套用設計稿。Canvas 可用來呈現正式素材與互動，不構成降低美術品質的理由。
- 工具、登入、費用、工期或效能限制不授權降低畫質。先完成不受阻的工作；若確實需要改動已核准的視覺，說明具體限制、差異與替代方案，取得使用者同意後才更換。不能先做簡化版，再以「技術限制」當作完成理由。
- 視覺調整不得順便修改已核准的玩法、資料、點數或追蹤契約。響應式、安全區與可讀性所需的微調應保留設計本質；影響角色造型或主要構圖的改動須另行確認。

## 交付前比對

以實際執行畫面截圖對照核准原圖，不用程式碼檢查或 Build 結果代替美術驗收。手機遊戲至少比較 390×844 CSS px 的遊玩畫面，以及受影響的待機與結算狀態。

逐項檢查：角色輪廓與頭身比、臉與表情、服裝與道具、動作辨識、場景透視與層次、線條與材質、色彩與光線、HUD 與操作區、角色大小與留白。提供核准稿與實作截圖的並排對照，清楚列出仍有的差異。

若第一眼就像換了一個人、換了一種畫風，或只剩配色接近，視覺驗收為 **FAIL**；繼續修正，不得以功能測試通過宣稱完成或稱「已套用設計稿」。區分功能測試、視覺比對與實機測試，各自回報實際結果。尚未達標的版本只能標示為未完成，不得發布為已核准成品。
