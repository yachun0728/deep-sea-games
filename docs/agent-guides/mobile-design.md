# 手機畫面與美術設定

## 手機優先與全螢幕畫面

2026-11-20 使用者指定，適用新增與改版的遊戲：

- 主要使用情境是手機。以直式約 390×844 CSS px 為第一設計目標，並依序檢查更窄與較矮的螢幕，以及 `env(safe-area-inset-*)`、`100dvh`；不得讓頁面水平捲動，主要操作需符合 44px 以上的點擊範圍，並放在單手拇指可及的位置。
- 進入遊戲後整個畫面就是遊戲區：不要再分「畫面區」與「操作面板／統計列」兩塊。分數、血量等狀態畫在畫面上方的 HUD 或 Canvas，主要操作直接做在畫面上（例如整個下半部是按鈕區），只有開始、結束結算等需要時才用浮層。實作可沿用 `games/blaster/style.css` 與 `games/campaign/style.css` 的做法：手機時 `position:fixed; inset:0`，Canvas 邏輯尺寸隨畫面高度調整，並保留一個明確的「退出遊戲」按鈕回大廳。
- 電腦版仍必須可玩（可以是置中的手機比例畫面、鍵盤／滑鼠操作，不得壞版或被切掉），但不是主要設計對象。若創作者提出電腦版專屬設計（寬螢幕多欄、側欄面板），Agent 應先提醒本站以手機版為主，請先確認手機版完整可玩，再把電腦版當作附加體驗，並說明兩者差異。
- 驗證：以實際 390px 寬度（可用 iframe 容器，不要只縮視窗；Chrome 最小視窗寬度會誤導）檢查待機、遊玩中與結束畫面，確認 HUD、操作區與退出按鈕不互相遮擋，再檢查桌面寬度。純繪圖調整不得更動玩法、扣點、追蹤與儲存契約。

## 手遊美術設定與確認流程

2026-11-20 使用者指定，適用每款手遊的新畫面設計與美術改版：

1. **先確認畫風。** 使用者已有指定畫風或參考圖時依其方向提案。方向未定時，可以先詢問偏好的畫風與想避開的元素，並提供二至三個符合玩法的選項，例如手繪、像素或卡通 3D。
2. **有角色就先交第一版角色設定集。** 用可看的概念圖呈現主要輪廓、配色、服裝或道具，以及遊玩時看得到的角度與代表動作。在手機比例的構圖中標出角色的位置與大小。請使用者確認角色是否可用，依回饋修改。
3. **每款都要交場景設定集。** 用概念圖呈現場景主題、視角、色盤、光線、材質及前中後景。至少附一張直式遊玩構圖，把角色（若有）、可操作區、障礙或互動物件和 HUD 放在同一張圖裡，方便確認整體搭配與辨識度。角色和場景可一起提案，等使用者確認兩者後才製作正式素材或實作新畫面。
4. **正式畫面要有遊戲自己的視覺語言。** 角色與道具應有清楚的輪廓、材質和用途，和場景共用一致的配色、造型與光線。避免用通用長方形堆出障礙、道具或整排面板，造成制式、AI 感重的畫面。長方形若符合物件本身的造型，可以保留，應能從細節看出它在遊戲世界裡是什麼。
5. **以實際遊玩畫面驗收。** 實作後提供 390×844 CSS px 的遊玩中截圖，確認角色、場景、障礙與 HUD 的大小和層次符合核准的構圖，並檢查較窄、較矮的手機畫面。
