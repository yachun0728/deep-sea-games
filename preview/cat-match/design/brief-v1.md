# TiCATiCA Cat Match｜遊戲企劃書（GDD）
版本：v1.0｜日期：2026-11-23｜狀態：開發規劃稿

## 1. 專案概述
- **遊戲名稱**：TiCATiCA Cat Match（貓貓三消）
- **類型**：休閒三消、關卡挑戰、無盡高分
- **平台**：HTML5，手機直式優先，桌面瀏覽器自適應
- **定位**：獨立開啟即玩的網頁小遊戲；**第一版不製作 Lobby、關卡地圖、商城、會員系統**。
- **體驗目標**：療癒軟萌但不幼稚、操作直覺、沒有倒數計時壓力、短時間可玩一關。
- **技術原則**：低伺服器成本、單人可維護、免登入、靜態資產優先。

## 2. 已確認需求與待定建議
### 已確認
1. 貓咪主題的原創三消，不能直接複製 Candy Crush 的美術與關卡。
2. 不規則棋盤，不能只有方形；棋盤要有足夠有效格數。
3. 四隻貓咪的隨身物可以成為 Icon；增加紙箱。
4. 所有遊戲圖案使用原創插畫，不使用 Emoji 當正式素材。
5. HTML 遊戲直接進入遊戲畫面，不先做 Lobby。
6. 角色、Icon、方格、棋盤形狀、遊戲主畫面已有**概念設定圖**，尚未全部切分為可直接使用的透明 PNG。
### 建議／尚待決策
- 同時支援關卡模式與無盡模式；MVP 先實作關卡模式，後續加入無盡模式。
- 基礎 Icon 每關選用 5–6 種，素材庫先備 8–12 種。
- 主力棋盤 8×8、9×9；7×7 教學，10×10 進階。
- 先以 30 關作 MVP，擴充到 100 關以上。
- 關卡進度先存 localStorage；排行榜待共用服務完成再接入。

## 4. 圖像素材與美術規範
### 4.1 基礎消除圖案
橘貓頭、灰貓頭、黑貓頭、奶油貓頭、貓掌、藍魚、毛線球、金鈴鐺、罐罐、蝴蝶結等作為素材候選。單關只取 5–6 款，避免畫面擁擠。

### 4.2 特殊消除
- **四連消**：生成方向性消除道具（橫列或直行）。
- **五連消**：生成彩虹貓咪／彩虹毛線球，與相鄰圖案交換後清除同類。
- **T／L 形消除**：生成範圍爆炸道具。
- **特殊道具互換**：觸發組合效果；需在規則表中定義，避免互相衝突。
- 建議特效：條紋魚、貓掌炸彈、禮物盒、彩虹球、星星魔杖。

### 4.3 障礙物
| 名稱 | 建議機制 |
|---|---|
| 普通紙箱 | 不可交換；鄰近消除一次後破壞 |
| 加固木箱 | 鄰近消除兩次後破壞 |
| 鎖鏈箱 | 需解鎖或受特殊消除命中 |
| 驚喜紙箱 | 破壞後釋放收集物或特殊圖案 |
| 冰塊 | 覆蓋圖案；在該格消除以減少耐久 |
| 藤蔓 | 阻擋交換或掉落，依關卡規則解除 |
| 石塊 | 不可交換、不可掉落，可能需特殊道具 |
| 傳送門／傳送帶 | 改變補充或移動路徑，不視為一般障礙 |

**設計約束**：紙箱作為「可消除基礎 Icon」和「阻擋棋盤的障礙物」時，必須採不同輪廓與材質，避免誤判。

### 4.4 棋盤方格與主題
- 森林木屋（預設）、海洋、魔法星空、櫻花；可逐步擴充雪地與遺跡。
- 方格底圖、格子狀態、消除 Icon、邊框、粒子特效**分層**。
- 建議單一方格原始素材 128×128 px，消除 Icon 256×256 px，透明 PNG 或 WebP。
- UI 必須支援繁體中文與英文；Logo／封面名稱可固定英文。
- 同一組 Icon 在 48–64 CSS px 顯示時仍需清晰可辨；不要只靠顏色辨識。

## 6. 核心玩法
1. 玩家點擊相鄰兩格，或以觸控滑動交換。
2. 若交換後形成水平／垂直至少三個相同圖案，執行消除；否則交換回原位。
3. 消除後處理障礙物傷害、分數與關卡目標。
4. 依重力方向掉落，從來源補新圖案。
5. 若產生連鎖，重複結算直到盤面穩定。
6. 更新剩餘步數、星級進度與目標；判定勝利或失敗。
7. 若盤面無合法交換，啟動洗牌。

### 6.1 關卡目標
- 指定分數
- 收集指定 Icon
- 清除紙箱／冰塊／藤蔓
- 將物件送到出口
- 複合目標

### 6.2 步數與節奏
- 以**步數限制**為主要挑戰，不採倒數計時。
- 道具數量、額外步數、失敗重試的資源消耗需在後續平衡設計決定。
- 提示功能在玩家停頓一段時間後顯示，但不強制自動操作。

## 7. UI／UX：獨立 HTML 遊戲
**直接進入遊戲，不做 Lobby 或關卡地圖。**

手機直式版面：
1. 頂部：Cat Match Logo、關卡數、星級進度、暫停／設定。
2. 目標列：剩餘步數、目標 Icon 與剩餘數量。
3. 中央：最大化不規則棋盤（優先保障點擊區與圖案辨識度）。
4. 底部：錘子、洗牌、彩虹球、貓掌手套等道具及剩餘次數。
5. 彈窗：教學、暫停、勝利、失敗、下一關／重試。

桌機以固定最大寬度置中，棋盤按視窗高度自適應；避免行動瀏覽器工具列遮擋底部按鈕。支援滑鼠點擊、拖曳及觸控滑動；不強制全螢幕。

## 8. 關卡與難度
| 階段 | 內容 |
|---|---|
| 1–10 | 7×7 至 8×8、三消教學、基本收集 |
| 11–20 | 8×8、四消五消、簡單紙箱 |
| 21–30 | 8×8 至 9×9、冰塊、複合目標、不規則形狀 |
| 31–60 | 藤蔓、石塊、環形、階梯、更多特殊消除 |
| 61–100 | 分區掉落、傳送門、複合障礙與高難度關卡 |

**平衡原則**：難度由目標、步數、圖案種類、障礙密度與盤面連通性共同決定，不能只靠減少格數。每關應進行自動模擬與人工試玩，追蹤通關率、平均剩餘步數、洗牌頻率及平均耗時。

## 9. 動畫與音效
- 交換：短距滑動與彈性回饋。
- 消除：縮放、閃光、粒子，不遮擋後續操作。
- 連鎖：分段音階與連鎖倍率提示。
- 掉落：帶輕微彈性的落地效果。
- 紙箱：裂紋、碎片；冰塊：碎裂；藤蔓：退縮。
- 角色：眨眼、揮掌、勝利歡呼。
- 提供靜音與減少動態效果選項；音效不依賴網路。

## 10. 技術架構
- **遊戲渲染**：建議 Phaser 3 或 Canvas 2D；HTML/CSS 負責 HUD 與彈窗。
- **遊戲邏輯**：純函式模組管理交換、匹配、特殊消除、障礙物、重力、洗牌與勝負。
- **關卡資料**：JSON；棋盤遮罩、掉落來源、目標、步數、障礙物、隨機種子分離管理。
- **儲存**：localStorage 儲存最高關卡、各關星級、設定；版本化並處理資料損壞。
- **部署**：靜態 HTML/JS/CSS/圖片，可部署 Cloudflare Pages/Workers。
- **追蹤**：可接既有 GA4 事件（`game_start`、`level_start`、`level_complete`、`level_fail`、`booster_use`），包含 `game_name`、`level_id`、`board_shape` 等欄位；注意不傳個資。
- **未來擴充**：登入、雲端進度、排行榜及共用 SDK，均不阻擋 MVP 上線。

## 11. 素材製作交付規格
- 每個 Icon 獨立透明 PNG/WebP，保留完整外框、陰影與適當留白。
- 消除 Icon 建議 256×256；方格底圖建議 128×128；角色立繪按實際畫面需求輸出。
- 檔名以英文小寫蛇形命名，例如 `tile_orange_cat.png`、`blocker_box_01.png`。

## 13. 驗收標準
1. 所有正式棋盤格數與遮罩資料一致，無錯誤空洞。
2. 每次穩定盤面至少有一個合法交換；無解時可自動洗牌。
3. 三消、四消、五消、T/L、連鎖及障礙結算結果可重現且正確。
4. 不規則棋盤不出現無法補充的可玩格。
5. 手機直式操作時棋盤與底部道具不被瀏覽器 UI 遮擋。
6. 無 Emoji 佔位素材混入正式版本。
7. 重新整理頁面後，已完成關卡與設定可恢復。
8. 不登入即可遊玩，靜態部署不依賴即時後端。
9. 遊戲畫面可正常退出、暫停與重新開始。
10. 圖片資產均有可追溯檔名、版本與授權狀態。

## 14. 開發順序
1. **美術定稿**：角色、Icon、方格、背景；完成切圖與透明度檢查。
2. **核心引擎**：盤面遮罩、交換、匹配、重力、補充、洗牌。
3. **玩法擴充**：特殊消除、障礙物、目標與勝敗。
4. **UI 整合**：手機直式、桌機適配、彈窗、音效。
5. **關卡製作**：30 關、難度測試、可玩性模擬。
6. **上線驗證**：跨裝置、效能、GA4、部署。
7. **後續擴充**：24 種形狀、無盡模式、更多關卡與角色收藏。
