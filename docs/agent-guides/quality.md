# 遊戲品質指南（參考 CrazyGames 品質準則）

2026-11-23 使用者指定：做新遊戲、改版或重新上架時都要對照本指南。內容整理自 CrazyGames 的 Quality guidelines（<https://docs.crazygames.com/requirements/quality/>），並對應到本站的做法。CrazyGames 另有強制的 requirements，若要真的上架到 CrazyGames，須另外核對原文。

本指南是品質方向，不取代 [遊戲產品原則](product-policy.md)（不得有博弈元素）、[手機畫面與美術設定](mobile-design.md) 與 [遊戲驗收與推送](release.md)。若有衝突，以本站既有規範為準並回報使用者。

## 1. 新手引導：讓玩家馬上開始玩

- 玩家一進遊戲就落在簡單的引導階段，引導直接做在遊戲玩法裡，不要另開一大頁說明。
- 只教核心操作，讓玩家能開始玩就好，不要一次解釋所有功能。
- 引導可以跳過。
- 以圖像示意為主，少用文字。用鍵盤按鍵圖示或手勢動畫告訴玩家怎麼操作（手機顯示觸控位置，桌機顯示按鍵）。
- UI 要清楚：
  - 按鈕文字清楚說明下一步，提示文字要寫按鈕上真正的名稱（例如「按「開始送餐」出發！」，不要寫「右側開始」）。
  - 按鈕大小不可刻意誘導點擊廣告或其他行為。
  - 按鈕不可故意延遲出現或延遲生效來混淆玩家。

## 2. 基本原則

- 有清楚、玩家達得到的目標。
- 容易學、容易懂：用字正確清楚，翻譯完整（繁中、英文、簡中都要通順），或善用通用圖示。
- 操作在整個遊戲中保持一致、直覺。

## 3. 好玩的條件

- 對玩家操作反應快，沒有明顯延遲。
- 挑戰、策略與節奏平衡，難度逐步上升。
- 畫面配置舒適直覺，重要資訊不被按鈕、訊息列或其他 UI 擋住。
- 音效舒適、與遊戲相符，不刺耳。
- 介面針對裝置設計：桌機必須好玩，手機（本站主要流量）也要好玩，並以 390×844 截圖驗收。
- 不同類型的玩家都能享受；故事或情境有趣（若有）。
- 沒有過度重複或無聊的操作。
- 資訊處理流暢，畫面不卡頓、不閃爍。
- 單人與多人：兩者都提供時，單人玩法要一樣明顯；不能單人玩時要清楚說明。

## 4. 獨特性

- 架構要方便日後加新內容（關卡、美術、故事元素）。
- 上架後不要改變遊戲類型等主要特色。
- 持續維護與更新。
- 名稱與圖示不能和別的遊戲容易混淆。
- 不使用通用名稱當遊戲名，除非擁有該 IP。例如「Super Chess」清楚又獨特，單叫「Chess」就不行；「Scrabble」是他人 IP，只有權利人能用。
- 不得模仿或重製他人遊戲、角色、商標或美術（例如樂高人偶與積木凸點、Minecraft 方塊外觀），也不要把別家遊戲截圖上傳給 GPT 當參考。

## 5. 美術與音效品質

- 圖像高品質：
  - 高解析度，整個遊戲解析度一致（Canvas 以 2 倍像素繪製）。
  - 沒有壓縮雜訊、去背白邊、殘留背景、缺角等瑕疵。
- 音效高品質：音量一致、不會忽大忽小，音樂配合畫面。
- 整體風格一致，不在寫實與卡通、高解析與低解析之間切換。素材、HUD、按鈕、文字框、封面都要是同一種風格。
- 遊戲本身要誠實：名稱、大廳封面與排行榜縮圖要如實呈現實際玩到的內容和類型，不誤導。只在大改版或視覺全面翻新時才更換名稱與封面。

## 6. 按鍵限制

- 操作直覺、容易學。
- 盡量讓按鍵配置跟著玩家的鍵盤佈局自動調整，而不是要玩家自己改設定。例如法國常用的 AZERTY 鍵盤，WASD 移動對應的是 ZQSD（可用 `KeyboardEvent.code` 判斷實體按鍵位置）。
- 避開瀏覽器已有用途的按鍵：
  - `Escape` 會關閉全螢幕，不要拿來當遊戲操作。
  - `Ctrl／Cmd + W` 會關閉分頁，只能在全螢幕時停用。

## 檢查清單

每次新增或改版遊戲，交付前逐項確認並在回報中說明哪些未驗證：

- [ ] 一進遊戲幾秒內就能開始玩，引導做在玩法裡、可跳過、以圖示為主。
- [ ] 按鈕文字與提示文字一致，沒有誘導或延遲的按鈕。
- [ ] 目標清楚，操作前後一致。
- [ ] 繁中、英文（與簡中顯示）用字正確，長句會斷行、不超出框。
- [ ] 手機 390×844 與桌機都可玩，UI 不互相遮擋，畫面不閃爍、不卡頓。
- [ ] 美術風格一致、解析度一致，素材沒有去背瑕疵。
- [ ] 音效音量一致、不刺耳。
- [ ] 名稱、封面、排行榜縮圖如實反映遊戲內容，不像他人作品或 IP。
- [ ] 沒有用 `Escape`、`Ctrl／Cmd + W` 當操作；有移動鍵時考慮鍵盤佈局。
