# Cross-Platform Compatibility & Performance

本文件規範 Deep Sea Arcade 所有遊戲在手機、平板及桌面裝置上的畫面相容性、操作體驗及執行效能。

所有新增、修改及驗收的遊戲，都必須依照本文件進行適用的跨裝置測試。

本文件的效能數值為專案開發目標，不代表 CrazyGames 官方硬性規定。

---

## 1. Supported Devices

遊戲應盡可能支援：

- 手機（iOS / Android）
- 平板（iPad / Android Tablet）
- 桌面電腦（Windows / macOS）
- 支援的行動及桌面瀏覽器

不得只以單一裝置或單一瀏覽器的測試結果宣稱跨平台相容。

---

## 2. Responsive Layout

### Mobile

- 支援常見手機螢幕尺寸。
- 主要遊戲畫面不得超出可視範圍。
- 按鈕及操作區域不得過小。
- 重要 UI 不得被瀏海、動態島或系統操作區遮擋。
- 不得出現不必要的水平捲動。
- 直式及橫式畫面應有合理處理方式。

### Tablet

- 適應平板不同尺寸及比例。
- 不得讓遊戲內容過度放大或縮小。
- UI 間距及操作區域應保持合理。

### Desktop

- 支援不同視窗大小及解析度。
- 縮放瀏覽器視窗時，遊戲畫面不得破版。
- 不得出現 UI 重疊、內容截斷或操作區域消失。
- 遊戲應合理利用可用畫面空間。

---

## 3. Input Compatibility

### Touch

- 支援觸控操作。
- 不得依賴 Hover 才能使用核心功能。
- 按鈕應具有合理的觸控範圍。
- 避免遊戲操作與瀏覽器滑動手勢衝突。
- 多點觸控若非必要，不應造成錯誤輸入。

### Mouse & Keyboard

- 滑鼠操作必須正常。
- 鍵盤操作必須符合遊戲設計。
- 不得讓瀏覽器預設操作意外干擾核心遊戲操作。
- 必要時提供清楚的操作提示。

---

## 4. Performance Targets

以下為專案目標：

- 一般遊戲場景以穩定 60 FPS 為目標。
- 低階裝置或高負載場景，應盡可能維持至少 30 FPS。
- 避免持續性掉幀及明顯卡頓。
- 避免不必要的記憶體及 CPU 使用。
- 避免大量不必要的圖片、動畫及重複運算。
- 資源載入應合理安排，避免阻塞主要遊戲操作。
- 不得因單次 FPS 數值正常，就宣稱整體效能通過。

測試時應記錄裝置、瀏覽器、測試場景及觀察結果。

---

## 5. Loading & Resource Management

- 必要資源應能正常載入。
- 載入失敗時應有合理處理方式。
- 避免重複下載或載入不必要的資源。
- 圖片應使用適當尺寸及格式。
- 動畫及音訊資源應控制使用量。
- 遊戲啟動時不得因非必要資源而長時間無回應。

---

## 6. Lifecycle & State Management

必須依遊戲功能測試：

- 切換瀏覽器分頁後返回遊戲。
- 手機切換 App 後返回遊戲。
- 手機鎖定螢幕後重新開啟。
- 瀏覽器重新整理。
- 遊戲暫停及恢復。
- 音訊靜音及恢復。
- 遊戲重新開始。

不得因切換背景或返回遊戲而導致重要狀態錯亂、重複計分或操作失效。

---

## 7. Cross-Device QA Checklist

### Mobile

- [ ] 主要遊戲畫面正常。
- [ ] UI 沒有重疊或溢出。
- [ ] 觸控操作正常。
- [ ] 按鈕可正常點擊。
- [ ] 直式及橫式處理正常。
- [ ] 音訊及暫停功能正常。
- [ ] 切換 App 後可正常恢復。
- [ ] 沒有明顯卡頓。

### Tablet

- [ ] 畫面比例正常。
- [ ] UI 配置合理。
- [ ] 觸控操作正常。
- [ ] 沒有內容截斷。
- [ ] 遊戲效能正常。

### Desktop

- [ ] 不同視窗尺寸下畫面正常。
- [ ] UI 沒有重疊或溢出。
- [ ] 滑鼠操作正常。
- [ ] 鍵盤操作正常。
- [ ] 音訊及遊戲狀態正常。
- [ ] 沒有明顯卡頓。

### Performance

- [ ] 已測試一般遊戲場景。
- [ ] 已測試高負載場景。
- [ ] 已觀察 FPS 及掉幀情況。
- [ ] 已檢查資源載入。
- [ ] 已檢查長時間遊玩是否出現效能下降。

## 8. Verification & Reporting

每次跨裝置驗收，必須記錄：

- 測試裝置及型號。
- 作業系統。
- 瀏覽器及版本。
- 螢幕尺寸或解析度。
- 測試的遊戲版本。
- FPS 或效能觀察結果。
- UI 與操作測試結果。
- 發現的問題及修正方式。

所有項目使用以下狀態：

- PASS：實際測試並通過。
- FAIL：測試未通過。
- NOT TESTED：尚未測試。
- BLOCKED：受環境或設備限制而無法測試。
- NOT APPLICABLE：不適用。

不得以桌面測試結果推論手機已通過，也不得以模擬器測試取代所有實機測試。

不得宣稱所有裝置都能順暢運行，除非有相應的測試證據。

---

## 9. Release Requirement

正式發布前：

- 核心遊戲功能必須完成適用裝置測試。
- 不得存在影響核心操作的重大跑版問題。
- 不得存在使遊戲無法正常遊玩的重大效能問題。
- 未完成的測試必須明確回報。
- 若裝置或瀏覽器尚未測試，必須列為未驗證範圍。

若發現重大相容性或效能問題，應先修正並重新驗收，再建議正式發布。
