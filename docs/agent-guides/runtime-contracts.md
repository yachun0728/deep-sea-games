# 遊戲與平台程式契約

## 必須維持的契約

- 不得任意更動 localStorage Key、資料格式或清除玩家既有資料。必要遷移需先說明相容讀取、遷移及回復方案；不得以重設資料解決錯誤。
- 共用錢包以 `S.balance`、`STORE` 與既有儲存／畫面更新流程為準。每局扣款、返還與 GA4 結束事件都必須避免重複執行。續關是否扣款、失敗是否返還，依各遊戲規則，不可套用統一假設。
- 尚未改造的舊程式中，倍率為含本金的總返還倍率；維護現況時不得誤算。此說明不是保留博弈機制的要求；經授權改造時應移除點數返還倍率與領回機制。分數、距離、選票與最佳紀錄不等於錢包點數。
- 不得破壞 GA4 追蹤事件、參數、遊戲 ID、回合生命週期與有效遊玩時間計算。使用既有 `window.deepSeaAnalytics`／`AN`，避免重複載入 Google tag、重複結算或傳送個人資料。詳見 [ANALYTICS.md](../../ANALYTICS.md)。
- 保持 GitHub Pages 靜態部署相容性：相對路徑、大小寫、hash 深連結、舊網址轉址及行動裝置操作需維持。不得要求伺服器端路由才能開啟遊戲。
- 不要為了重構而引入不必要的框架、套件、建置流程或後端。現況沒有 npm 專案，不要虛構 `npm test`／`npm run build`。
- `templates/`、`games/`、`js/`、`css/` 是可編輯來源；`index.html` 是已追蹤的部署產出，禁止直接修改。修改後執行 `python3 tools/build.py`，再以 `python3 tools/build.py --check` 確認同步。不要編輯被忽略的 `crush-depth.html`。
- 目前 JS 是組合進同一個原有 IIFE 的來源片段，不是各自獨立的 ES module。保留 `js/runtime.js` 引用順序與共用作用域，不要直接新增多個 script 標籤載入這些片段。優先維持相同產出；獨立化 API 是後續需另評估的行為相容重構。
- 珍奶遊戲保留原嵌入畫面，透過 `deepSeaBoba` 橋接扣點與追蹤；未經要求不得改造其 UI。驗證 iframe 來源與暫停／恢復流程。
- 2026-11-18 使用者指示：全站免費遊玩（`START_BALANCE=0`、`ENTRY_FEE=0`），已移除頁首「重設為 500 點」按鈕與處理程式，並取消「低於 100 點每分鐘回 1 點」。不得擅自加回；舊文件中的入場費／重設／回點描述為歷史紀錄。平台固定獎勵（每分鐘 2 點、每日 60 點、每款首次完成 +5 點）與獨立造型頁 `#wardrobe` 依 `GAME_RULES.md` 末段，獎勵須與投入無關。不得擅自加入儲值、付款或對外傳訊。
