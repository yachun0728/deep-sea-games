# CrazyGames 版本更新與遊戲 QA

這是 TiCATiCA 的內部驗收流程，整理自 TOP DOGGO 更新經驗，不是新增的官方審核門檻。官方要求仍依 skill 所列來源重新核對。只更新文件時，不因此執行部署、清除存檔、上傳或送審。

## 先固定被測版本

- 記錄遊戲、日期、Basic／Full 階段、來源 revision、ZIP 檔名與 SHA-256；來源未提交時另記 dirty 狀態與關鍵來源雜湊，不能讓舊 commit 看起來代表全部內容。
- 保存已交付 ZIP，用新版本檔名產出更新包。解壓最終 ZIP 至新目錄，以 HTTP 測根層入口；來源頁、build 目錄與解壓包不是同一份證據。
- 更新關卡資料／獨立腳本時檢查快取版本是否同步，測舊頁重載能讀到相容的新程式與資料。
- 分開列出靜態檢查、自動邏輯測試、本機瀏覽器、真機、Portal QA Tool、正式審核／發布。某一層通過，不推論其他層通過。

## 按變更選擇檢查

| 變更 | 實測與斷言 |
| --- | --- |
| 關卡／任務 | 各受影響關卡可開始、正確計進度、成功只結算一次；失敗可重試，通關可續關／重玩。確認目標不只換名稱，玩法條件與挑戰確有差異；難度與趣味仍需真人試玩。 |
| 限時／守點／護送 | 計時只在有效遊玩進行；暫停、背景、教學不偷跑。離開區域／目標被阻擋／下車等條件依設計正確生效；超時後按鈕真的重開，不恢復已結束的回合。 |
| 多階段／頭目 | 提早擊敗目標不致卡關；階段切換重建必要目標及標記；一般擊倒與指定頭目不可互相誤計，最後階段結束一次。 |
| 教學／輸入 | 提示明寫裝置對應的按鍵／按鈕名稱，例如桌機「按 Q 換武器」。親自觸發該輸入，確認實際武器／動作已改變後才前進；不能僅靠按鈕被點擊判完成。核心操作維持可用，提示不遮擋。 |
| 存檔／解鎖 | 全新、既有版本、損毀及儲存被拒的情況；重載、續玩、重玩、最後一關上限、自由模式隔離。任務索引改動需相容限制或遷移，記錄哪些進度保留、哪些依設計重新開始，不清玩家資料代替修正。 |
| HUD／導航 | 目標、數量、倒數與階段清楚；遠處任務／頭目標記能辨認。390×844 為內部手機檢查，再依宣告裝置與官方 iframe 尺寸驗收；選關長大後分頁／捲動與末頁仍可操作。 |
| 音訊／效能 | 選單與遊玩切換不疊播；暫停、失焦、背景、靜音恢復正確。依新增負載檢查敵人／粒子上限與長時間表現；記錄裝置、瀏覽器、時長、FPS／掉幀及發熱觀察。桌機模擬不等於 Safari 真機測試。 |
| SDK／獨立包 | 真實遊玩、暫停、結束的 start／stop，SDK 延遲／失敗、平台靜音優先。mock 測試只證明 adapter 邏輯；平台事件必須在本版 Portal 預覽／QA Tool 另驗。檢查原站連線與跨平台殘留。 |

對有多關的遊戲，關卡設定檢查與測試捷徑可協助逐關開局，但不能宣稱已真人通關全部關卡。依變更範圍實玩完整循環；未完整遊玩的關卡要列明，尤其限時難度、護送可達性與最終頭目平衡。

## 測試工具與證據邊界

- 優先測可觀察行為：真實任務狀態轉移、完成一次、存檔相容及操作結果；不要只比對提示文字或複製實作來自證。
- 測試用選關按鈕、無敵、傳送、快轉或預設進度放在獨立 QA 副本。不得進入上傳 ZIP，也不得把這種測試寫成人類正常遊玩通關。
- 瀏覽器隱藏／背景時動畫可能停跑；畫面成功載入不足以證明計時、移動及戰鬥正常。記錄這項限制，改用可執行的前景測試或將該項標示未驗證。
- 截圖記錄版本與 viewport。舊錯誤修正後重跑失敗情境；只將新測試證據更新為 PASS，保留未解決限制。
- QA 後若修改了遊戲來源，重新打包並重驗受影響項目；最終報告與雜湊必須對應交付 ZIP。

## 交付紀錄

在 `output/publishing/crazygames/<game-slug>/` 留存版本對應報告（ZIP 外）：

| 項目 | 狀態 | 版本／環境 | 證據／限制 |
| --- | --- | --- | --- |
| ZIP／語法／資源 | NOT TESTED | 待填 | 待實測 |
| 任務與核心循環 | NOT TESTED | 待填 | 列出實玩／捷徑／自動測試各自涵蓋範圍 |
| 教學與操作 | NOT TESTED | 待填 | 實際輸入與結果 |
| 存檔／重載／重玩 | NOT TESTED | 待填 | 既有存檔相容策略 |
| 手機與效能 | NOT TESTED | 待填 | 模擬與真機分列 |
| SDK mock／Portal | NOT TESTED | 待填 | 分列，不合併為 SDK 全通過 |
| 正式審核／發布 | NOT TESTED | 待填 | 只依平台實際結果更新 |

狀態使用 PASS、FAIL、NOT TESTED、BLOCKED、NOT APPLICABLE。BLOCKED 寫明原因；不適用項寫明理由。交付說明列出待辦與是否建議送審，不因 ZIP 建置成功就建議正式發布。

Update Notes 只描述已完成的玩家可見改動；「降低負載」需有對應改動，沒有測量時不寫成「解決發熱」「所有裝置流暢」。提交遊戲包、送出 QA、正式送審與發布各自記錄，不由文件或本機測試推定完成。
